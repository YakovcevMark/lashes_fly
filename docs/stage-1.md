# Этап 1. Вход в кабинет мастера

Панель открывается как самостоятельный сайт на телефоне и компьютере. Прямая ссылка на кабинет оканчивается на `/#/panel`. Вход через Telegram возвращает мастера на тот же сайт. Сервер разрешает доступ одному Telegram ID и выдаёт сессию на 7 дней. Мастер может завершить её раньше.

## Локальный запуск

Требуются Node.js 22.13 или новее, Yarn Classic 1.22.22 и PostgreSQL 18. Для запуска PostgreSQL из проекта подойдёт Docker Compose. Выполняйте команды из корня репозитория.

1. Установите зависимости командой `yarn install --frozen-lockfile`.
2. При первом запуске создайте `.env` из `.env.example` (`Copy-Item .env.example .env` в PowerShell). Заполните настройки ниже.
3. Запустите базу командой `docker compose up -d --wait postgres`. Для уже установленного PostgreSQL укажите его строку подключения в `DATABASE_URL`.
4. Выполните `yarn build:api` и `yarn migrate`. Повторный запуск миграций сохраняет данные.
5. Запустите `yarn dev` и откройте [кабинет на этом компьютере](http://localhost:5173/#/panel). Команда запускает панель, сервер, пересборку TypeScript и обработчик фоновых заданий.

HTTP-сервер и обработчик можно запускать отдельно после сборки командами `yarn start:api` и `yarn start:worker`. Каждую минуту обработчик удаляет просроченные попытки входа и сессии. При проверке запроса API учитывает срок сессии сразу.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Строка подключения к PostgreSQL для сервера, миграций и обработчика |
| `POSTGRES_PASSWORD` | Пароль при первоначальном создании локальной базы в Docker Compose |
| `PORT` | Порт HTTP API, по умолчанию 3000 |
| `ADMIN_URL` | Полный адрес возврата на панель с завершающим слешем, без параметров и фрагмента. Для Pages используется `https://yakovcevmark.github.io/lashes_fly/` |
| `MASTER_TELEGRAM_ID` | Разрешённый числовой ID мастера для проверки на сервере |
| `SESSION_TTL_DAYS` | Срок сессии в днях, по умолчанию 7 |
| `TELEGRAM_CLIENT_ID`, `TELEGRAM_CLIENT_SECRET` | Серверные реквизиты Telegram Login из настроек тестового бота в BotFather |
| `TELEGRAM_BOT_USERNAME`, `TELEGRAM_BOT_TOKEN` | Имя без @ и токен Bot API для проверки тестового бота командой `yarn bot:check` |
| `VITE_API_BASE_URL` | Публичный базовый адрес API вместе с `/api/v1`. Локально работает прокси Vite. Для Pages задайте абсолютный HTTPS-адрес в переменных GitHub Actions |
| `TEST_DATABASE_URL` | Адрес базы для интеграционных тестов. Тесты создают и удаляют собственную схему |

Для входа откройте в BotFather настройки выбранного бота → **Login Widget**. Добавьте точный `ADMIN_URL` в **Allowed URLs**, скопируйте Client ID и Client Secret в окружение сервера. Выберите алгоритм подписи RS256 (стандартная настройка Telegram). Для проверки подключения через Bot API заполните отдельно токен бота и выполните `yarn bot:check`. [Документация Telegram Login](https://core.telegram.org/bots/telegram-login)

## GitHub Pages

В Settings → Pages источник публикации — **GitHub Actions**. После каждого push в `main` workflow проверяет типы, линтер, сборки и вход на чистой PostgreSQL. После успешных проверок GitHub публикует содержимое `apps/admin/dist`. В pull request выполняются проверки.

[Адрес панели](https://yakovcevmark.github.io/lashes_fly/) · [Прямая ссылка на кабинет](https://yakovcevmark.github.io/lashes_fly/#/panel) · [Запуски публикации](https://github.com/YakovcevMark/lashes_fly/actions/workflows/pages.yml)

Панель можно опубликовать до появления хостинга API. В этом случае экран входа сообщает, что ожидает подключения сервера. Для включения входа:

1. На выбранном хостинге задайте серверные переменные, установите зависимости, выполните `yarn build:api` и `yarn migrate`. Запустите HTTP-сервер и обработчик отдельными процессами. Откройте HTTP-сервер по HTTPS.
2. В Settings → Secrets and variables → Actions → **Variables** укажите `VITE_API_BASE_URL` со значением вида `https://api.example.org/api/v1`. В клиентскую сборку попадает только публичный адрес API.
3. Зарегистрируйте адрес Pages в BotFather и повторите публикацию из `main` с помощью **Run workflow** или нового push. Переменные Vite читаются при сборке.

## Контракт и проверка

API использует префикс `/api/v1`. Машиночитаемая спецификация хранится в `packages/api-contract/openapi.yaml`, общие типы — в `packages/api-contract/index.ts`.

Сервер создаёт одноразовую попытку входа на пять минут. Браузер сохраняет привязку попытки в текущей вкладке и переходит на Telegram. После возврата сервер обменивает код с помощью PKCE, проверяет подпись, издателя, аудиторию, срок и свежесть ID-токена, затем сверяет Telegram ID из подписанного профиля. Сервер хранит хеш выданного случайного ключа сессии. Для работы Pages с отдельно размещённым API панель хранит ключ в localStorage своего origin и передаёт его как Bearer. Сайты под одним origin имеют доступ к его localStorage, включая другие проекты этого аккаунта на github.io. Для отдельной границы хранения используйте свой домен панели.

Для автоматической проверки выполните `yarn typecheck`, `yarn lint`, `yarn build`. Задайте `TEST_DATABASE_URL` в окружении процесса и выполните `yarn test`. Для проверки подходит отдельная тестовая база PostgreSQL с правом создания схем. В тестах Telegram заменён локальным издателем подписанных ответов.

Для приёмки на телефоне:

1. Откройте прямую ссылку на кабинет в новой приватной вкладке. Появится экран входа.
2. Войдите через Telegram как мастер. Кабинет покажет ваш Telegram ID и дату окончания сессии. Обновите страницу по прямой ссылке.
3. Нажмите «Выйти из кабинета» и снова откройте прямую ссылку. Сайт предложит войти.
4. Войдите через другой Telegram-аккаунт. Сайт покажет отказ в доступе, API вернёт 403. Повторите вход мастера на компьютере.
